## Advisory assessment and available fixes

- **CVE-2026-53914:** product-wide Kotlin CPE misidentification on the listed standard libraries, compiler runtimes and Dokka plugins. [OSV/GHSA-r937-wjx7-w2jp](https://api.osv.dev/v1/vulns/GHSA-r937-wjx7-w2jp) identifies `org.jetbrains.kotlin:kotlin-gradle-plugin`, fixed in 2.4.20-Beta1 (stable 2.4.20). The project already uses 2.4.21. The [upstream fix](https://github.com/JetBrains/kotlin/commit/bf51df665b458fda7c3eaf436c4d88dc119d7ec6) changes KAPT incremental cache code. Inspection found no KAPT cache classes in the matched compiler-embeddable jars. Dokka's plugin version is not a Kotlin language version. Do not upgrade Dokka to an unrelated version number to satisfy a Kotlin CPE.
- **CVE-2026-56740 / CVE-2026-56741:** genuine vulnerable JLine telnet code is present in lint's compiler jar (`org/jline/builtins/telnet/TelnetIO.class`). Ten embedded module POMs cause duplicate product matches; the advisory identifies `jline-remote-telnet`. Fixed library releases exist: 3.30.14, 4.0.16 and 4.2.1, per [OSV 56740](https://api.osv.dev/v1/vulns/GHSA-47qp-hqvx-6r3f) and [OSV 56741](https://api.osv.dev/v1/vulns/GHSA-2r2c-cx56-8933). Android lint does not start a telnet server, so the network attack path is not exercised by this build. Adding a normal JLine constraint cannot replace already embedded classes.
- **CVE-2022-3171 / CVE-2024-7254:** compiler metadata identifies protobuf-java 2.6.1, but the jar contains 277 relocated Kotlin protobuf entries and zero `com/google/protobuf/` entries. Independent bytecode review found `CodedInputStream.skipField(int, CodedOutputStream)` recursing through `skipMessage` for wire type 3 without recursion-depth checks: the unsafe nested-group pattern described by CVE-2024-7254 is present. CVE-2022-3171 remains unresolved pending verification of the fork against its fix. Relocation alone does not prove a false positive. Denial of service requires hostile protobuf input; lint reads Kotlin metadata from source/dependencies, rather than serving network requests. [OSV 3171](https://api.osv.dev/v1/vulns/GHSA-h4h5-3hr4-j3g2) lists fixes 3.16.3, 3.19.6, 3.20.3 and 3.21.7. [OSV 7254](https://api.osv.dev/v1/vulns/GHSA-735f-pc8j-v9w8) lists 3.25.5 and 4.27.5. A standalone protobuf dependency does not replace this relocated fork.
- **CVE-2012-2055:** scanner misidentification of `io.github.oshai:kotlin-logging-android:8.0.4` as GitHub Enterprise. The [GitHub vendor notice](https://github.blog/news-insights/public-key-security-vulnerability-and-mitigation/) concerns Rails public-key mass assignment. Its fixed GitHub Enterprise release is 20120304; that version has no relationship to this Kotlin logging AAR.
- **CVE-2008-0986:** scanner misidentification of `com.android.tools.analytics-library:protos:32.4.1` as an early Android SDK native image decoder. The jar contains Java protobuf messages, no native `.so` or `libsgl.so` decoder. The [Android vendor notice](https://android-developers.googleblog.com/2008/03/android-sdk-update-m5-rc15-released.html) identifies SDK m5-rc15 as the fix; that historical SDK version is not a Maven protos version.

Additional matches below Dependency-Check’s configured CVSS threshold also remain visible: CVE-2020-29582 on Kotlin versions newer than the [vendor’s 1.4.21 fix](https://blog.jetbrains.com/blog/2021/02/03/jetbrains-security-bulletin-q4-2020/); CVE-2023-50572 on embedded JLine modules without the [affected Groovy component](https://github.com/jline/jline3/issues/909); CVE-2021-22569 on the relocated protobuf fork, pending verification ([OSV fixes 3.16.1, 3.18.2 and 3.19.2](https://api.osv.dev/v1/vulns/GHSA-wrvw-hg22-4m67), with javalite unaffected); and CVE-2026-54285 on Java OpenTelemetry 1.66.0. [OSV for the last advisory](https://api.osv.dev/v1/vulns/GHSA-8988-4f7v-96qf) identifies npm `@opentelemetry/core`, fixed in 2.8.0; these Java packages are an ecosystem mismatch.

## Bundled-tool blocker and owner decision

[Google Maven AGP metadata](https://dl.google.com/dl/android/maven2/com/android/tools/build/gradle/maven-metadata.xml) and [lint compiler metadata](https://dl.google.com/dl/android/maven2/com/android/tools/external/com-intellij/kotlin-compiler/maven-metadata.xml) show 9.4.1 / 32.4.1 as the newest stable releases at inspection. Inspection of the newest compiler prerelease, 32.5.0-alpha09, still found JLine 3.24.1 and relocated protobuf 2.6.1. There is no fixed **stable lint compiler artifact in this registry snapshot**; the standalone JLine/protobuf fixes above exist. Moving to the alpha would not fix these embedded versions.

The remaining decision belongs to the owner: request a patched lint compiler upstream, authorize replacement/rebuilding of the tool with reviewed embedded fixes, or adjudicate the bounded build-time exposure and scanner misidentifications. No acceptance, suppression or waiver is applied here. The unfiltered security blocker is not resolved merely because the configured audit passes.
